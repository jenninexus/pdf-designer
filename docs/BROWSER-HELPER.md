# Application Helper (local prototype)

This Manifest V3 extension helps fill ordinary job application fields after you import an explicitly approved JSON profile. It runs only after you open the extension and choose **Review this page**. Review every proposed value, including field labels: matching is conservative but a site can label a field ambiguously. Existing values and less-specific name, job title and company matches are unchecked; checking an existing value explicitly authorizes overwriting it. Fill acts only on selected fields, binds the review to the same browser document and URL, and skips changed controls. If the browser cannot identify the document, review fails closed. The application itself remains yours to review and submit.

## Try it locally

1. Create a private starter from your local person record with `python browser-extension/export-profile.py <user>`. It writes `resumes/<user>/resources/browser-helper-profile.json` without overwriting. An explicit `--output <private-path>` is also supported. Inside this checkout, output is restricted to that user’s `resumes/<user>/resources/` folder; outside it, choose a private location. Review and edit the file before import; it includes only the person name, default contact email, and website when present. Alternatively copy `browser-extension/profile.example.json` to a private location and replace its examples. Do not commit private data.
2. In Chrome or Edge, open the browser's extensions page, enable developer mode and load the `browser-extension` folder as an unpacked extension.
3. Open an application page, open the helper from its browser toolbar button or with Ctrl+Shift+Y (Command+Shift+Y on macOS), import the JSON, select **Review this page**, check desired matches and select **Fill selected fields**. Browsers may let you change the shortcut in their extensions settings. Repeat on each new page.
4. **Remove saved profile** deletes the stored profile. The browser may retain its own backups or filesystem data outside the extension's control.

Version 1 accepts only the fields in the example plus `fullName`. All are optional single-line strings; unknown keys are rejected. Source personal details from the local `users/<person>.json` contact information and source current role and company from confirmed vault claims. Manually copy and approve only what you want disclosed; the résumé rendering profile is not an applicant-data export. The helper displays the imported field values for review. The exporter does not infer values or read the vault, PDFs or files automatically. Never import the full vault or an application record.

Only standard visible text, email, telephone and URL inputs with unambiguous exact labels are matched, in the top frame. Dropdowns, custom controls, iframes and fields with sensitive or ambiguous labels are left for manual entry. It does not fill demographic, work authorization, salary or free-text answers, upload files, or submit forms. Site scripts can observe values entered into their own fields; local storage is not encryption against someone with access to the browser profile. No account, Google login, cloud sync, billing or store publication exists in this slice.

The extension requests `activeTab`, `scripting`, and `storage`, without persistent all-site host permissions. It restricts local storage to trusted extension contexts before loading or saving; if the browser does not support that restriction it fails closed. Only selected values are passed into the current page's isolated script, and there is no message endpoint. The browser grants temporary access on invocation ([Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)); local storage access can be restricted using [setAccessLevel](https://developer.chrome.com/docs/extensions/reference/api/storage/StorageArea). Edge supports the Chromium extension API with compatibility testing required ([Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/developer-guide/port-chrome-extension)).

Testing: use a disposable local form and the public example profile. Verify empty fields fill and fire input/change events, filled fields stay untouched until checked, changed fields are skipped, and no submit or file upload occurs. Test both Chrome and Edge before distribution. Browser pages and cross-origin frames that cannot be scripted are unsupported.

Exporter checks: `python -m unittest discover -s browser-extension -p test_export_profile.py`. Helper logic checks: `node browser-extension/test-helper.cjs`. Browser integration still requires Chrome and Edge testing.

Routed pre-release checks loaded the unpacked extension and imported the public profile in bundled Chromium. Its fill mechanism was also exercised in isolated-world DOM fixtures in bundled Chromium and Edge. A complete toolbar or keyboard-triggered application workflow in branded Chrome and Edge remains a release gate.
